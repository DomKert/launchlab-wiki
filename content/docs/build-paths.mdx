Three recipes to a live landing page. Pick the one that matches your comfort, your appetite for tokens, and what you actually want to learn this weekend.

These are starting points, not requirements. If you already use Webflow, Squarespace, Cursor, v0, or anything else, use it. The deliverable is a live URL with a working CTA, not the recipe.

The Spellbook prompts upstream of the build (Prompts 1, 2, 3, 9, 14, 15, 16, 18) all run regardless of which recipe you pick. The recipe only changes what happens at build time.

## Decision tree

If you want the cleanest output for the least friction: **Recipe Chat**.

If you specifically want a chat-driven build environment with a live preview pane and accept the daily token cap: **Recipe Builder**.

If you want to learn how coding agents run a build, or you're already on Claude Code or Codex: **Recipe Agent**.

If you change your mind mid-sprint: any recipe can hand off to any other. Copy your `index.html` and your hero image, paste into a fresh chat or builder, keep going. The upstream Spellbook work (copy, style, hero image, OMTM, distribution plan) all transfers.

## Recipe Chat

Talk to a chat model. It writes the full HTML. You save the file, drag the folder to Netlify Drop. Live URL in under 10 minutes.

Tools that fit Recipe Chat (any one is fine, free tier on all):

- **ChatGPT free.** GPT-5.3 for 10 messages per 5-hour window, then silent drop to GPT-5.3-mini. Spend the GPT-5.3 window on hero copy and the build prompt.
- **Claude free.** Sonnet 4.6 with Adaptive Thinking. 30 to 100 messages per day.
- **Gemini 2.5 Flash free.** 1M context window. Good when you want to feed the full Spellbook outputs as context.
- **DeepSeek free.** R1 reasoning. Public content only (conversations are stored in China, heads-up not a block for a landing page).
- **Kimi free.** 2M context window. Same public-content caveat.

The flow:

1. Run [Prompt 17 Build prompt](/docs/prompts/bolt-build) in your brain (Claude Project, ChatGPT Project, or Codex) to synthesize a build prompt.
2. Paste Claude's output into a fresh chat in your chosen tool. Get the full HTML in a code block.
3. Copy the HTML, save locally as `index.html`. Any text editor works.
4. If you have a hero image file from [Prompt 18](/docs/prompts/hero-image-prompt), save it next to `index.html` and update the `<img src="...">` to match the local filename.
5. Sign up for a free [Netlify](https://app.netlify.com/signup) account. Drag your folder onto [app.netlify.com/drop](https://app.netlify.com/drop). Live URL like `https://your-site-abc123.netlify.app`.
6. Iterate: edit `index.html` directly, or paste the current HTML into a fresh chat with "change X", get patched HTML back, redeploy.

The Netlify account matters. Anonymous Drop deploys disappear after a few hours; signing up claims the site.

Strengths: chat models are heavy on clean web design, first-try output tends to be polished. No daily token cap on most. Total cost zero.

Weaknesses: no live preview while editing. To see changes, save and open in a browser. Iteration is slower than a builder's chat-driven loop.

Best for: most students, especially anyone who wants the cleanest path with no platform lock-in.

## Recipe Builder

Chat-driven build environment with a live preview pane. Two free options. You pick one.

- **[Bolt.new](https://bolt.new) free.** 1M tokens per month, daily 300K is the binding cap. Live preview pane, file editor, one-click publish to a `.bolt.host` URL.
- **[Lovable.dev](https://lovable.dev) free.** 5 credits per day, 30 per month. Roughly 2 to 3 prompts per day. Chat-driven React and Supabase build environment.

Both have similar shapes. Both have daily caps. Students pick by feel.

The flow with Bolt or Lovable:

1. Run upstream Spellbook prompts as usual (4-box, OMTM, copy, AI smell strip).
2. Run [Prompt 17 Build prompt](/docs/prompts/bolt-build) in your brain to synthesize the build prompt.
3. Open Bolt or Lovable. Paste the assembled build prompt as your first message.
4. Bolt: don't toggle Plan mode (it reads the auto-scaffolded Vite tree and burns 250K tokens). Skip the Design System dropdown.
5. After scaffold, verify the file sidebar shows ONLY `index.html`. If extras present, follow up with a delete-everything-except-index.html message.
6. Iterate via direct file edits in the builder's editor (zero tokens) for most changes; re-prompt only for restructures.
7. Publish via the one-click button.

If you hit the daily cap mid-sprint, switch to Recipe Chat: paste your `index.html` into a fresh ChatGPT or Claude chat, keep iterating, redeploy via Netlify Drop.

Strengths: AI chat iteration with live preview, fastest feedback loop when it works, the most "vibecoding" of the three recipes.

Weaknesses: daily token cap is real on both. Bolt's auto-scaffolded Vite tree adds re-sync cost on every prompt.

Best for: students who specifically want the AI iteration UX as a learning experience.

## Recipe Agent

A coding agent in your terminal reads your context files and writes the build. The newest of the three. Requires comfort with a terminal but not actual code knowledge. The agent does the typing.

Two free options:

- **[Claude Code](https://docs.claude.com/en/docs/claude-code/overview).** Anthropic's terminal agent. Requires Anthropic Pro+ for sustained use. Free with the Anthropic free credits during the trial.
- **[Codex](https://chatgpt.com/codex).** OpenAI's CLI. Free with a limited trial allowance, sustained access via ChatGPT Plus, or **the India ChatGPT Go 12-month unlock**, which gives Codex sustained access free for a year for +91 SIM holders.

The flow with Claude Code or Codex:

1. Run upstream Spellbook prompts as usual. Save your context files (`one-liner.md`, `customer.md`, `research-brief.md`, `4-box.md`, `landing-copy.md`) to a working directory on your machine.
2. Open a terminal in that working directory. Launch `claude` (Claude Code) or `codex`.
3. Tell the agent: "Read my context files. Build a single-file static HTML landing page (`index.html`) for [PROJECT NAME] using the cleaned copy in `landing-copy.md`. Tailwind via CDN, Google Fonts via link tag, button-links for CTAs, no iframes, no build step."
4. The agent writes `index.html`. You can ask it to iterate ("the hero feels heavy, lighten the background").
5. When it looks right, drag the folder to Netlify Drop or push to a GitHub repo with Netlify auto-deploy.

India unlock note: ChatGPT Go is free for 12 months for +91 SIM holders. Activates via UPI or card with a small refunded charge. Unlocks Codex sustained access plus GPT-5.3 Instant, image gen, file uploads. Auto-renews at ₹399/month after 12 months unless cancelled. Set a phone reminder for month 11.

Strengths: the agent reads your full context on every turn. No copy-paste between tools. Versionable via git. Closest to how shipped software is built in 2026.

Weaknesses: terminal UX is unfamiliar to first-time founders. Less visual feedback than Recipe Builder during iteration. Codex on free needs the India unlock or a Plus subscription for sustained use after the trial.

Best for: students who want to learn how coding agents work, or who are on the India ChatGPT Go unlock and want to spend their Codex access.

## Multi-AI relay

A workflow that beats single-tool builds: don't use one tool for everything. Sequence:

1. Scaffold with Gemini, ChatGPT, or Claude. Explain what you want and ask for HTML with placeholders as HTML comments where you'll fill in real content. You get back base HTML with structural placeholders like `<!-- HERO HEADLINE HERE -->`, `<!-- SUBHEAD -->`, `<!-- CTA BUTTON TEXT -->`.

2. Hand-edit at marked spots. Open `index.html` in any text editor. Wherever the scaffold left a placeholder comment, replace it with plain text. No coding needed; you're typing your hero headline, subhead, CTA copy directly into the file at marked positions.

3. Polish with Claude. Paste the edited HTML into a fresh Claude chat. Ask it to add animations, smooth scroll, fix rendering bugs, tighten responsive layout. Claude is the polish layer.

Why it works:

- Different models have different strengths. Gemini is fast at structural HTML; Claude has a stronger polish and refactor instinct (animations, edge cases, bugs); ChatGPT sits in between.
- Contributing plain text at marked spots means body copy is yours, not AI-generated voice. Less work for [Prompt 9 Strip AI smell](/docs/prompts/strip-ai-smell) later.
- Each model has one job. Don't ask one model to scaffold and polish; you burn tokens and get worse output on both ends.

Stacks on top of Recipe Chat (deploy via Netlify Drop) and Recipe Agent (commit, deploy). Recipe Builder runs inside its own preview environment so the relay there is between Bolt and Lovable.

## Trade-off table

| Recipe | Token cost | First-try quality | Iteration speed | Best for |
|------|-----------|-------------------|-----------------|----------------------|
| Chat | $0 | High | Medium (text editor + redeploy) | Default, no platform lock-in |
| Builder | Daily cap | Variable | Fast (chat + preview) | Learning the chat-driven build UX |
| Agent | Trial cap (free) | High when context-fed | Fast (terminal + commit) | India unlock holders, terminal-comfortable |

## Switching recipes mid-sprint

You're not locked in. Each recipe outputs the same artifact: a single `index.html` plus any hero image. Copy those two files into a fresh chat, builder, or terminal and pick up where you left off.

The upstream Spellbook work (copy, style direction, hero image, OMTM, distribution plan) all transfers across recipes.
