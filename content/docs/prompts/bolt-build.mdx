## Why this works

The build prompt has a lot of moving parts: project name, all section copy, vibe keyword, mood, type, CTA destination, hero image plan. Filling it into a static template by hand means missing something.

Claude reads your Project knowledge (4-box, customer, one-liner, OMTM, plus bolt-copy.md and style-spec.md if saved) and walks you through the missing pieces one at a time. If you're missing a prereq (no style spec, no Tally form, no cleaned copy), Claude stops and routes you back. Then it outputs the final build prompt as one code block.

This runs in Claude Project. The OUTPUT goes to ChatGPT (Path A) or Bolt (Path C).

## Before you run this

Five things ready in your Project knowledge or available to paste:

1. Cleaned section-by-section copy from [Prompt 4](/docs/prompts/landing-page-spec) → [Prompt 9](/docs/prompts/strip-ai-smell). Save as `bolt-copy.md` in Project knowledge or be ready to paste. ALL sections of the page (hero + each subsequent section per OMTM shape), not just hero.

2. Style spec from [Prompt 16](/docs/prompts/visual-direction). Save as `style-spec.md`. The simplified spec is just vibe keyword + 3 mood adjectives + Google Fonts pairing. No palette hex codes (we dropped that since it produces muddy output).

3. CTA destination set up. [Tally form](https://tally.so) URL for waitlist, [Cal.com](https://cal.com) URL for demos, [Stripe Payment Link](https://stripe.com/payments/payment-links) for e-com, mailto: for 1:1.

4. Hero image plan decided. Either an image file saved to disk (from [Gemini Nano Banana](https://gemini.google.com), [gpt-image-2](https://chatgpt.com), or [Unsplash](https://unsplash.com) download), or "use a placeholder for now", or "no image, type-only".

5. (Optional, fallback only) The 3 reference screenshots from Prompt 16 saved in a folder. Won't get attached to the build tool by default; vibe keyword in input 2 is the compressed version.

If any of inputs 1 to 4 are missing, Claude will stop and tell you which to do first.

## Prompt

Run this in your Claude Project chat. Claude walks you through 5 inputs one at a time, then outputs the final build prompt as one code block.

```txt
I'm ready to build my landing page. Read my Project knowledge (4-box.md, customer.md, one-liner.md, OMTM, plus bolt-copy.md and style-spec.md if I've saved them) and synthesize the single build prompt I'll paste as the first message in either ChatGPT (Path A, default) or Bolt (Path C).

The prompt MUST do three things to survive free tier limits and produce clean output:
1. Ask for a single-file static HTML landing page (one index.html only, Tailwind via CDN script tag in the head, Google Fonts via link tag, custom CSS in a style block, no Next.js, no Vite, no framework, no separate config files)
2. Ask for the WHOLE page in one shot (all sections from my cleaned copy)
3. Use button-links for forms (Tally / Cal.com / Stripe), NOT iframes or embeds. Embeds break too often.

Walk me through these inputs one at a time, in order. Don't ask all at once. Pull from Project knowledge first if the answer is already there.

1. Project name (the brand or product name as it appears on the site)
2. Cleaned section-by-section copy from Prompt 9 (ALL sections, not just hero): hero headline + subhead + CTA, plus every subsequent section's content per the OMTM shape (problem block, what-you-offer, social proof slot, final CTA, etc.)
3. Style spec from Prompt 16: vibe keyword + 3 mood adjectives + Google Fonts pairing. NO palette hex codes (the build tool picks its own).
4. CTA destination URL: Tally form for waitlist, Cal.com link for demo, Stripe Payment Link for e-com, mailto: for 1:1
5. Hero image plan: confirm I have a hero image file saved to disk, OR say "placeholder", OR say "no image"

If I'm missing a prereq (no style spec, no CTA URL, no cleaned copy), STOP. Tell me which Spellbook prompt or tool I need to complete first. Don't fabricate values.

When you have all five, output the final build prompt as ONE code block I can copy and paste. Use this exact structure with my values substituted:

---

[For Bolt path only: I will attach the hero image file via the paperclip if I have one. For ChatGPT path: I'll save the image alongside the index.html locally.]

FIRST INSTRUCTION (token discipline, applies if you scaffold by default): This project must be exactly ONE file: index.html. No package.json, no vite.config.js, no main.js, no src/ folder, no public/ folder, no tsconfig.json, no node_modules. If your starting state has any of those files, your FIRST action is to delete every file except index.html (or create index.html if it doesn't exist). Don't scaffold a framework. Don't add a build step.

Build the FULL landing page for [PROJECT NAME] inside that single index.html. Mobile-first. Tailwind via CDN script tag in the head, Google Fonts via link tag in the head, custom CSS in one style block in the head. Build all sections in one go.

Style direction (light spec, let your defaults breathe)
Vibe keyword: [vibe keyword from style spec]
Mood: [3 mood adjectives from style spec]
Type: headlines in [Google Font from spec], body in [Google Font from spec]. [one sentence on weight and contrast from spec]

Pick a palette and detailed type sizing that match the vibe keyword and mood. Default to a clean off-white or warm cream background with high-contrast charcoal or near-black type. Use ONE accent color for the primary CTA only. No saturated full-page background colors. No alternating section backgrounds. Generous whitespace, type-driven layout.

Section copy (use verbatim, don't rewrite or improvise)
[Substitute every cleaned section from bolt-copy.md, in order, with section labels per OMTM shape.]

CTA wiring (use button-links, NOT iframes)
Primary CTA button text: [paste from cleaned hero copy]
Primary CTA destination: [Tally URL / Cal.com URL / Stripe URL / mailto:]
The hero CTA button and the final-section CTA button BOTH link directly to this URL with target="_blank" rel="noopener noreferrer". Do not embed forms via iframe. Do not use anchor scroll to an in-page form. Just two button-links to the same destination URL.

Hero image
[Founder choice as ONE line: "I've attached the hero image file. Embed it in the hero, full-bleed or right-aligned per the vibe." OR "Use a placeholder.com gradient sized 1600x900 for the hero, I'll swap later." OR "No image. Type-only hero with generous whitespace, no decorative blocks, no gradients."]

Stack constraints (repeat for emphasis)
- ONE file: index.html. Nothing else.
- Tailwind: <script src="https://cdn.tailwindcss.com"></script> in head
- Google Fonts: standard <link> tag in head
- Custom palette (if you extend Tailwind): inline tailwind.config object inside a <script> block, not a separate file
- Custom CSS: inline <style> block, only if Tailwind utilities aren't enough
- No build step, no npm

Constraints
- No corporate stock photo people
- No "Trusted by 10,000+" social proof I haven't given you
- No floating UI cards
- No gradient hero blocks
- No saturated full-page background colors
- No iframe embeds for forms (always button-link)
- Mobile must look right first, desktop second
- Single page, no nav, no separate routes

Build the full landing page in one go. All sections, one file. Strip the scaffold first if needed, then build.

---

Voice rules for the assembled prompt: don't add anything that's not in my Project knowledge or that I haven't given you. No fabricated stats, no extra sections, no improvised copy, no testimonials. If a value is missing, ask for it instead of guessing.
```

## Path A. ChatGPT free + Netlify Drop (default, recommended)

Best for most students. Better output than Bolt for static landing pages, zero token cliff.

1. Open [free ChatGPT](https://chatgpt.com). Paste Claude's assembled prompt as a single message.
2. ChatGPT outputs the full HTML in a code block (60 to 90 seconds). Click the copy button at the top of the code block.
3. Save the HTML locally as `index.html` in any folder. Use any text editor (TextEdit on Mac, Notepad on Windows, or [VS Code free](https://code.visualstudio.com/)).
4. If you have a hero image file from Prompt 18, save it in the SAME folder as `index.html` and reference it in the HTML as `<img src="hero.jpg">` (or whatever you named it). Edit the HTML to point at the local filename if ChatGPT used a placeholder.
5. Sign up for a free [Netlify](https://app.netlify.com/signup) account. Drag your folder onto [app.netlify.com/drop](https://app.netlify.com/drop). Free, instant URL, signing up means the deploy persists. Without an account, anonymous Netlify Drop URLs disappear after a few hours.
6. To iterate: edit `index.html` in your text editor (or paste the current HTML into a fresh ChatGPT chat with "change X please"), drag onto Netlify Drop again to deploy a fresh version.

Trade-off: no live preview while editing, no AI iteration UI in the same place. But for a static landing page where the spec is locked, ChatGPT generates working HTML first try in 99% of cases. Most iteration is small text/color tweaks anyway.

## Path C. Bolt (advanced, only if you want the AI iteration loop)

Best for students who specifically want the AI iteration UI with live preview pane. Comes with the 300K daily token cap risk.

### Don't toggle Plan mode

Bolt's docs say Plan mode saves tokens, which is true for complex multi-file builds. For single-file static HTML it's the opposite. Bolt auto-scaffolds a Vite template the moment you arrive at bolt.new, and Plan mode reads that whole Vite tree as context. A single Plan generation can cost 250K tokens before any code is built. The assembled prompt above already contains the plan.

Click **Build now** directly. Don't toggle Plan.

### Skip the Design System dropdown

Those are Next.js component libraries (Shadcn, Material UI, etc.) and we're asking for single static HTML. Picking one wastes the slot.

### Attach the hero image only

Click the paperclip icon and attach your hero image file from Prompt 18 if you generated one (10MB limit, free tier). That's the only image that needs to be in Bolt because it becomes content embedded in the HTML.

Don't attach the 3 reference screenshots from Prompt 16. They cost input tokens on every message and the vibe keyword already captures the visual direction.

### Paste and run

Paste Claude's assembled prompt as your first message and click Build. Wait 60 to 120 seconds.

After scaffold, check the file sidebar. If it shows ONLY `index.html`, you're good. If you see `package.json`, `vite.config.js`, etc., send one follow-up: "Delete every file in the project except index.html. The project must contain exactly one file."

For copy edits, color tweaks, padding, image swaps, individual section content: open `index.html`, edit the line, save. Zero tokens. Most refinement happens here.

If you hit the daily cap, see [vibecoding workflow when you hit the wall](/docs/vibecoding/workflow#when-you-hit-the-wall). The hero comes with you in a Cursor migration.

## Need a hero image first?

Use [Prompt 18 Hero image prompt](/docs/prompts/hero-image-prompt) to synthesize the image-gen prompt in Claude (same pattern as this one), then paste into Gemini Nano Banana, gpt-image-2, or Ideogram. Download the image file to disk. For Path A: save next to your index.html. For Path C: attach via paperclip.

## What good looks like

One Claude Project chat session, 5 turns, final assembled build prompt in one code block.

Path A: paste into free ChatGPT, get HTML, save to disk, drag to Netlify Drop (with free account so it persists). Live URL in under 10 minutes, zero token cost. Iteration via text editor + redeploy.

Path C: paste into Bolt with hero image attached, Build directly (no Plan mode), full landing page in 60 to 120 seconds, file sidebar shows only index.html. Direct edits in `index.html` for refinement. Token budget under 100K of 300K daily cap.

## What bad looks like

Path A: signing up for Netlify but forgetting to claim the deploy site, so the URL expires. Or trying to edit the HTML in a chat instead of a text editor and getting confused.

Path C: toggling Plan mode on (Plan reads the Vite scaffold = 250K). Letting Bolt scaffold Next.js + config files and re-syncing them on every prompt. Using iframe embeds for forms (Tally embed renders blank too often).

Both paths: providing extracted hex codes from Prompt 16 (we dropped that, it produced muddy palettes). Asking for hero only and burning follow-ups on adding sections.
