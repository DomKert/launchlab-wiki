## Why this works

The Bolt prompt has a lot of moving parts: project name, palette, type, vibe keyword, all section copy, CTA destination, hero image plan. Filling all of that into a static template by hand means missing something and hitting a wall mid-paste.

Claude reads your Project knowledge (4-box, customer, one-liner, OMTM, plus bolt-copy.md and style-spec.md if saved) and walks you through the missing pieces one at a time. If you're missing a prereq (no style spec, no Tally form, no cleaned copy yet), Claude stops and routes you back to the right Spellbook prompt or tool. Then it outputs the final Bolt prompt as one code block you paste straight into Bolt.

This runs in Claude Project, not Bolt. The OUTPUT goes to Bolt (or ChatGPT, see Path B below) and asks for the whole landing page as one `index.html` file so the free tier survives the sprint.

## Before you run this

Five things ready in your Project knowledge or available to paste:

1. Cleaned section-by-section copy from [Prompt 4](/docs/prompts/landing-page-spec) → [Prompt 9](/docs/prompts/strip-ai-smell). Save as `bolt-copy.md` in Project knowledge or be ready to paste. This includes ALL sections of the page (hero, problem, what-you-offer, social proof, final CTA, etc., per the OMTM shape) not just the hero.

2. Style spec from [Prompt 16](/docs/prompts/visual-direction). Save as `style-spec.md` or be ready to paste.

3. CTA destination set up. [Tally form](https://tally.so) for waitlist, [Cal.com](https://cal.com) for demos, [Stripe Payment Link](https://stripe.com/payments/payment-links) for e-com, mailto: for 1:1. You need the actual URL or email.

4. Hero image plan decided. Either an image file saved to disk (from [Gemini Nano Banana](https://gemini.google.com), [gpt-image-2](https://chatgpt.com), or [Unsplash](https://unsplash.com) download), or "use a placeholder for now", or "type-only, no image". The hero image is the ONLY file that attaches to Bolt.

5. (Optional, fallback only) The 3 reference screenshots from Prompt 16 saved in a folder. You won't attach these to Bolt by default. The style spec in input 2 is already the compressed text version, and image attachments cost Bolt tokens on every message.

If any of inputs 1 to 4 are missing, Claude will stop and tell you which to do first.

## Prompt

Run this in your Claude Project chat. Claude walks you through 5 inputs one at a time, then outputs the final Bolt prompt as one code block.

## Path A. Bolt (with iteration loop)

Use this if you want a live preview pane and AI-driven iteration after the first build.

### Don't toggle Plan mode

Bolt's docs say Plan mode saves tokens, which is true for complex multi-file builds. For single-file static HTML it's the opposite. Bolt auto-scaffolds a default Vite template the moment you arrive at bolt.new, and Plan mode reads that whole Vite tree as context to generate the plan. A single Plan generation can cost 250K+ tokens before any code is even built. The assembled prompt above already contains the plan, so adding Plan mode just doubles the work.

Click **Build now** directly. Don't toggle Plan.

### Skip the Design System dropdown

Those are Next.js component libraries (Shadcn, Material UI, etc.) and we're asking for a single static HTML file. Picking one wastes the slot.

### Attach the hero image only

Click the paperclip icon and attach your hero image file from Prompt 18 if you generated one (10MB limit, free tier). That's the only image that needs to be in Bolt because it becomes content embedded in the HTML.

Don't attach the 3 reference screenshots from Prompt 16. They cost input tokens on every message and the style spec already captures the visual direction in compressed text form.

### Paste and run

Paste Claude's assembled prompt as your first message and click Build. Wait 60 to 120 seconds for the page to scaffold.

After the scaffold, check Bolt's file sidebar. If it shows ONLY `index.html`, you're good. If you see `package.json`, `vite.config.js`, or any other files, send one follow-up: "Delete every file in the project except index.html. The project must contain exactly one file."

Then check the preview pane. Don't prompt yet. Read the file, click around, decide what's actually wrong vs what just needs a tweak.

For copy edits, color tweaks, padding, image swaps, individual section content: open `index.html`, edit the line, save. Zero tokens. Most refinement happens here.

Reserve Bolt re-prompts for restructures (new layout, feature touching multiple sections, bug you can't track down by editing). One change per prompt.

Full vibecoding loop: [vibecoding workflow](/docs/vibecoding/workflow). When you hit the wall: [recovery section](/docs/vibecoding/workflow#when-you-hit-the-wall).

## Path B. ChatGPT free + Netlify Drop (no token cost)

Use this if your Bolt token cap is depleted, or you want the simplest possible flow with zero tokens spent.

1. Open [free ChatGPT](https://chatgpt.com). Paste the same assembled prompt Claude generated above as a single message.
2. ChatGPT outputs the full HTML in a code block. Click the copy button.
3. Save the HTML locally as `index.html` in any folder. Use any text editor (TextEdit on Mac, Notepad on Windows, or VS Code free).
4. Open [Netlify Drop](https://app.netlify.com/drop) in your browser. Drag the folder containing `index.html` (or just the file) onto the drop zone. You get an instant live URL. Free, no signup needed.
5. To iterate: edit `index.html` in your text editor, drag onto Netlify Drop again to deploy a fresh version.

Trade-off: no live preview while editing, no AI iteration loop in a UI. But for a static landing page where the spec is locked, ChatGPT generates working HTML first try in 99% of cases. Most of your iteration will be small text/color tweaks anyway.

For a hybrid path: generate in ChatGPT, then paste the resulting HTML into a fresh Bolt project as the first message ("Use this exact HTML, no changes, just preview it: [paste]") to get Bolt's preview pane without burning tokens on generation.

## What good looks like

One Claude Project chat session, 5 turns, final assembled build prompt in one code block.

Path A (Bolt): paste with hero image attached, Build directly (no Plan mode), full landing page in 90 to 120 seconds, file sidebar shows only index.html. The rest is direct edits in `index.html`. Token budget under 100K of the 300K daily cap. Live URL on `.bolt.host` by Friday night.

Path B (ChatGPT + Netlify Drop): paste, copy HTML, save locally, drag to Netlify Drop. Live URL in under 5 minutes, zero Bolt tokens spent. Iteration via text editor + redeploy.

## What bad looks like

Toggling Plan mode on with single-file HTML. Plan ingests the auto-scaffolded Vite tree and burns 200K+ tokens generating a plan you don't need. The assembled prompt already contains the plan.

Letting Bolt scaffold Next.js + Tailwind config + layout files instead of catching it in the FIRST INSTRUCTION block. If after Build you see `package.json` or `vite.config.js` in the sidebar, follow up with "delete every file except index.html" before doing anything else.

Asking for hero only and burning 5 follow-up prompts on adding sections one at a time. The single-file approach makes whole-page-in-one-prompt the cheaper path.
