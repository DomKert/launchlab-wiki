## Why this works

The Bolt prompt has a lot of moving parts: project name, palette, type, vibe keyword, hero copy, CTA destination, hero image plan, plus 3 reference screenshots to attach. Filling all of that into a static template by hand means missing one and hitting a wall mid-paste.

Claude reads your Project knowledge (4-box, customer, one-liner, OMTM) and walks you through the missing pieces one at a time. If you're missing a prereq (no style spec, no Tally form, no headline yet), Claude stops and routes you back to the right Spellbook prompt or tool. Then it outputs the final Bolt prompt as one code block you copy straight into Bolt.

This runs in Claude Project, not Bolt. The OUTPUT goes to Bolt and asks for a single-file HTML landing page so the free tier survives a full sprint.

## Before you run this

Five things ready in your Project knowledge or available to paste:

1. Cleaned section-by-section copy from [Prompt 4](/docs/prompts/landing-page-spec) → [Prompt 9](/docs/prompts/strip-ai-smell). Save as `bolt-copy.md` in Project knowledge or be ready to paste.

2. Style spec from [Prompt 16](/docs/prompts/visual-direction). Save as `style-spec.md` or be ready to paste.

3. CTA destination set up. [Tally form](https://tally.so) for waitlist, [Cal.com](https://cal.com) for demos, [Stripe Payment Link](https://stripe.com/payments/payment-links) for e-com, mailto: for 1:1. You need the actual URL or email.

4. Hero image plan decided. Either an image file saved to disk (from [Gemini Nano Banana](https://gemini.google.com), [gpt-image-2](https://chatgpt.com), or [Unsplash](https://unsplash.com) download), or "use a placeholder for now", or "type-only, no image". You'll attach the file to Bolt alongside the 3 reference screenshots.

5. (Optional) Screenshots from Prompt 16 saved in a folder. You won't attach these to Bolt by default (the style spec in input 2 is the compressed text version, and image attachments cost Bolt tokens). Keep them on hand only as a fallback if Bolt's first scaffold is way off the vibe and you need a visual course-correct later.

If any of inputs 1 to 4 are missing, Claude will stop and tell you which to do first.

## After Claude outputs the Bolt prompt

Three pre-build choices on Bolt's side: turn on Plan mode, attach files, paste. Skip the Design System picker on the homepage; it's for Next.js component libraries (Shadcn, Material UI, etc.) and doesn't apply to single-file HTML.

### Turn on Plan mode

Click the Plan toggle in the prompt toolbar (next to the Build now button). Plan mode makes Bolt write a build plan first that you review and edit before any code generates. Bolt's own docs flag this as the top token-saving tactic. The cheapest place to catch a bad assumption is in the plan, not after Bolt has scaffolded the wrong thing and burned tokens.

### Attach files (only the hero image)

Click the paperclip icon and attach your hero image file from Prompt 18 if you generated one (10MB per file, free tier). That's the only image that needs to be in Bolt because it becomes content embedded in the HTML.

Don't attach the 3 reference screenshots from Prompt 16. They cost input tokens on every message and the style spec already captures the visual direction in compressed text form. Keep the screenshots in a folder as a fallback only: if Bolt's first scaffold is way off vibe, you can attach 1 to 2 of them in a follow-up prompt to course-correct visually.

### Paste and run

Paste Claude's assembled prompt as your first message. Bolt writes the plan, you review and edit (especially: confirm the plan says "one HTML file" and not "Next.js project"), then click Build. Wait 60 to 90 seconds for the hero scaffold.

Don't prompt yet after the scaffold appears. Read the file, click around, decide what's actually wrong vs what just needs a tweak.

For copy edits, color tweaks, padding, hero image swaps: open `index.html`, edit the line, save. Zero tokens.

For new sections (problem block, what-you-offer, CTA, social proof): one prompt per section, referencing the established hero style. "Add the next section to index.html using the same palette, type, and radius as the hero. Section content: [paste cleaned copy from Prompt 9]."

Full vibecoding loop and the keep / change / add pattern: [vibecoding workflow](/docs/vibecoding/workflow). When you hit the wall: [recovery section](/docs/vibecoding/workflow#when-you-hit-the-wall).

## What good looks like

One Claude Project chat session, 5 to 6 turns, final assembled Bolt prompt in one code block. Paste into Bolt with screenshots and hero image attached, hero scaffold in 90 seconds. 5 to 8 follow-up Bolt prompts max for the rest of the page (one per section, plus a few tweaks). The rest is direct edits in `index.html`. Live URL on `.bolt.host` by Friday night, token budget under 200K of the 300K daily cap.

## What bad looks like

Skipping the synthesizer and trying to fill the Bolt template by hand. Or letting Bolt default to Next.js + Tailwind scaffold ignoring the single-file constraint. Or skipping Plan mode and letting Bolt scaffold the wrong thing on first prompt. All three burn the daily cap before the page is live.

If you ever see Bolt's plan mention `tailwind.config.ts`, `app/layout.tsx`, `globals.css`, `package.json`, or `node_modules`, STOP. Tell Bolt: "Single index.html only, Tailwind via CDN script tag, no separate config files. Rewrite the plan." Catching this in plan mode costs nothing. Catching it after scaffold costs the daily cap.
