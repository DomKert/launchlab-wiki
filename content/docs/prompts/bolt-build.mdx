## Why this works

The Bolt prompt has a lot of moving parts: project name, palette, type, vibe keyword, all section copy, CTA destination, hero image plan. Filling all of that into a static template by hand means missing something and hitting a wall mid-paste.

Claude reads your Project knowledge (4-box, customer, one-liner, OMTM, plus bolt-copy.md and style-spec.md if saved) and walks you through the missing pieces one at a time. If you're missing a prereq (no style spec, no Tally form, no cleaned copy yet), Claude stops and routes you back to the right Spellbook prompt or tool. Then it outputs the final Bolt prompt as one code block you paste straight into Bolt.

This runs in Claude Project, not Bolt. The OUTPUT goes to Bolt and asks for the whole landing page as one `index.html` file so the free tier survives the sprint.

## Before you run this

Five things ready in your Project knowledge or available to paste:

1. Cleaned section-by-section copy from [Prompt 4](/docs/prompts/landing-page-spec) → [Prompt 9](/docs/prompts/strip-ai-smell). Save as `bolt-copy.md` in Project knowledge or be ready to paste. This includes ALL sections of the page (hero, problem, what-you-offer, social proof, final CTA, etc., per the OMTM shape) not just the hero.

2. Style spec from [Prompt 16](/docs/prompts/visual-direction). Save as `style-spec.md` or be ready to paste.

3. CTA destination set up. [Tally form](https://tally.so) for waitlist, [Cal.com](https://cal.com) for demos, [Stripe Payment Link](https://stripe.com/payments/payment-links) for e-com, mailto: for 1:1. You need the actual URL or email.

4. Hero image plan decided. Either an image file saved to disk (from [Gemini Nano Banana](https://gemini.google.com), [gpt-image-2](https://chatgpt.com), or [Unsplash](https://unsplash.com) download), or "use a placeholder for now", or "type-only, no image". The hero image is the ONLY file that attaches to Bolt.

5. (Optional, fallback only) The 3 reference screenshots from Prompt 16 saved in a folder. You won't attach these to Bolt by default. The style spec in input 2 is already the compressed text version, and image attachments cost Bolt tokens on every message. Keep them on hand only as a fallback if Bolt's first scaffold is way off vibe and you need a visual course-correct in a follow-up prompt.

If any of inputs 1 to 4 are missing, Claude will stop and tell you which to do first.

## Prompt

Run this in your Claude Project chat. Claude walks you through 5 inputs one at a time, then outputs the final Bolt prompt as one code block.

## After Claude outputs the Bolt prompt

Two pre-build choices on Bolt's side: turn on Plan mode, attach the hero image. Skip the Design System picker on the homepage; it's for Next.js component libraries (Shadcn, Material UI, etc.) and doesn't apply to single-file HTML.

### Turn on Plan mode

Click the Plan toggle in the prompt toolbar (next to the Build now button). Plan mode makes Bolt write a build plan first that you review and edit before any code generates. Bolt's own docs flag this as the top token-saving tactic. The cheapest place to catch a bad assumption is in the plan, not after Bolt has scaffolded the wrong thing and burned tokens.

### Attach the hero image only

Click the paperclip icon and attach your hero image file from Prompt 18 if you generated one (10MB limit, free tier). That's the only image that needs to be in Bolt because it becomes content embedded in the HTML.

Don't attach the 3 reference screenshots from Prompt 16. They cost input tokens on every message and the style spec already captures the visual direction in compressed text form. Keep the screenshots in a folder as a fallback only: if Bolt's first scaffold is way off vibe, you can attach 1 to 2 of them in a single follow-up prompt to course-correct visually.

### Paste and run

Paste Claude's assembled prompt as your first message. Bolt writes the plan, you review and edit. Two checks before clicking Build:

1. Plan says "one HTML file" or "index.html only" and NOT "Next.js project", "Vite app", "tailwind.config.ts", or any separate config files.
2. Plan covers ALL the sections you gave it (hero plus the rest of bolt-copy.md), not just the hero.

If either check fails, edit the plan inline. Tell Bolt: "Single index.html only, Tailwind via CDN script tag, build ALL sections from the prompt in one go, no separate config files." Then Build. Catching this in plan mode costs nothing. Catching it after scaffold costs the daily cap.

Wait 60 to 90 seconds for the page to scaffold.

Don't prompt yet after the scaffold appears. Read the file, click around, decide what's actually wrong vs what just needs a tweak.

For copy edits, color tweaks, padding, image swaps, individual section content: open `index.html`, edit the line, save. Zero tokens. Most refinement happens here, not in Bolt re-prompts.

Reserve Bolt re-prompts for restructures (a new layout, a feature that touches multiple sections, fixing a bug you can't track down by editing). One change per prompt. Use the keep / change / add pattern from [Vibecoding Principle 6](/docs/vibecoding/principles).

Full vibecoding loop: [vibecoding workflow](/docs/vibecoding/workflow). When you hit the wall: [recovery section](/docs/vibecoding/workflow#when-you-hit-the-wall).

## Need a hero image first?

Use [Prompt 18 Hero image prompt](/docs/prompts/hero-image-prompt) to synthesize the image-gen prompt in Claude (same pattern as this one), then paste into Gemini Nano Banana, gpt-image-2, or Ideogram. ## What good looks like

One Claude Project chat session, 5 turns, final assembled Bolt prompt in one code block. Paste into Bolt with the hero image attached. Plan mode review confirms single-file HTML and all sections. Click Build. Full landing page in 90 to 120 seconds. The rest of the work is direct edits in `index.html`, which cost zero Bolt tokens. Live URL on `.bolt.host` by Friday night, token budget under 100K of the 300K daily cap.

## What bad looks like

Letting Bolt default to Next.js + Tailwind scaffold ignoring the single-file constraint. Or asking for hero only and then burning 5 follow-up prompts on adding sections one at a time. Or skipping Plan mode and watching Bolt scaffold the wrong thing on first prompt. All three burn the daily cap before the page is live.

If you ever see Bolt's plan mention `tailwind.config.ts`, `app/layout.tsx`, `globals.css`, `package.json`, or `node_modules`, STOP. Tell Bolt: "Single index.html only, Tailwind via CDN script tag, build all sections in one go, no separate config files. Rewrite the plan." Catching this in plan mode costs nothing. Catching it after scaffold costs the daily cap.
