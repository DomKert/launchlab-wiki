## The flow

Get prereqs ready → paste the meta-prompt below in Claude → Claude walks you through 5 inputs one at a time → Claude outputs your assembled build prompt as one code block → paste that into ChatGPT (Path A) or Bolt (Path C) → live URL.

Path A is the default. Path C trades simpler iteration for a live preview pane plus a 300K daily token cap. Path B (zero AI, Carrd or Framer) skips this prompt entirely; see [Pick your build path](/docs/build-paths).

### Path C. Bolt (advanced, only if you want the AI iteration loop)

Best for students who specifically want the AI iteration UI with live preview pane. Comes with the 300K daily token cap risk.

#### Build

Paste Claude's assembled prompt as your first message and click **Build now** directly. (Don't toggle Plan mode, see below.) Wait 60 to 120 seconds.

After scaffold, check the file sidebar. If it shows ONLY `index.html`, you're good. If you see `package.json`, `vite.config.js`, etc., send one follow-up: "Delete every file in the project except index.html. The project must contain exactly one file."

For copy edits, color tweaks, padding, image swaps, individual section content: open `index.html`, edit the line, save. Zero tokens. Most refinement happens here.

If you have a hero image file from Prompt 18, click the paperclip icon and attach it (10MB limit, free tier). That's the only image that needs to be in Bolt because it becomes content embedded in the HTML.

#### Don't toggle Plan mode

Bolt's docs say Plan mode saves tokens, which is true for complex multi-file builds. For single-file static HTML it's the opposite. Bolt auto-scaffolds a Vite template the moment you arrive at bolt.new, and Plan mode reads that whole Vite tree as context. A single Plan generation can cost 250K tokens before any code is built. The assembled prompt above already contains the plan.

#### Skip the Design System dropdown

Those are Next.js component libraries (Shadcn, Material UI, etc.) and we're asking for single static HTML. Picking one wastes the slot.

#### Reference screenshots cost tokens on every message in Bolt

Bolt re-charges input tokens for attached images on EVERY follow-up message you send, not just the first one. Across 10 to 20 iterations that drains the 300K daily cap fast. Two options if you have a reference screenshot:

- Attach it to your FIRST build message only, then iterate without it. Works if you keep iterations under 10.
- Skip the screenshot and use the vibe vocab fallback for Path C.

If you want heavy reference-screenshot use, switch to Path A. Free ChatGPT has no equivalent per-message image cost.

#### If you hit the daily cap

Migrate to [Cursor](https://cursor.sh) free tier: copy `index.html` and your hero image into a fresh Cursor project, paste the latest prompt that worked into Cursor's chat, keep iterating. The hero comes with you.

## What good looks like

One Claude Project chat session, 5 turns, final assembled build prompt in one code block.

Path A: paste into free ChatGPT, get HTML, save to disk, drag to Netlify Drop with a free account so it persists, rename the subdomain to your brand, create per-channel Dub.co tracking links. Live URL in under 10 minutes, zero token cost. Iteration via the same ChatGPT chat plus redeploy.

Path C: paste into Bolt with hero image attached, Build directly (no Plan mode), full landing page in 60 to 120 seconds, file sidebar shows only index.html. Direct edits in `index.html` for refinement. Token budget under 100K of 300K daily cap.

## What bad looks like

Path A: dragging the folder onto Netlify Drop without signing up, so the URL expires after a few hours. Or shipping with the auto-generated `your-site-abc123.netlify.app` URL because you didn't rename the subdomain. Or sharing the bare Netlify URL across every channel and not knowing later which post drove the clicks.

Path C: toggling Plan mode on (Plan reads the Vite scaffold = 250K). Letting Bolt scaffold Next.js + config files and re-syncing them on every prompt. Using iframe embeds for forms (Tally embed renders blank too often).

Both paths: feeding the AI builder explicit palette hex codes. Vision-extracted palettes consistently produce muddy output because the builder follows the codes literally and loses what makes the reference work. Let the vibe keyword carry the palette decision. Also: asking for hero only and burning follow-ups on adding sections.
