## Before you start

Open these in tabs.

1. The assembled Bolt prompt from [Prompt 17](/docs/prompts/bolt-build) (one code block Claude synthesized in your Project chat, asks for single-file HTML not Next.js).
2. Your hero image file from Prompt 18 if you generated one (you'll attach this; reference screenshots stay in their folder as a fallback only).
3. [bolt.new](https://bolt.new), signed in.
4. Your Claude Project tab kept open so you can feed back follow-up section prompts without burning Bolt tokens on planning.

## The 6-step sequence

### 1. Pre-build setup. Skip Plan mode, attach hero image only.

Skip the Design System dropdown on the bolt.new homepage. Those are Next.js component libraries (Shadcn, Material UI, etc.) and we're asking Bolt for a single static HTML file, not a Next.js project. Picking one wastes the slot.

Skip Plan mode too. Bolt's docs flag Plan mode as a token-saver for complex builds, but for single-file static HTML it's the opposite. Bolt auto-scaffolds a Vite template the moment you arrive at bolt.new, and Plan mode reads that whole Vite tree as context before generating the plan. A single Plan generation can burn 250K+ of the 300K daily cap before any code is built. The assembled prompt from [Prompt 17](/docs/prompts/bolt-build) already contains the plan; Plan mode just adds an expensive turn that re-ingests the scaffold.

Click the paperclip and attach your hero image file from Prompt 18, if you generated one (10MB limit, free tier). The hero image becomes content embedded in the HTML, so it earns its keep in Bolt.

Reference screenshots are different. Bolt re-charges input tokens for attached images on every follow-up message, so a reference screenshot drains the 300K daily cap fast across 10+ iterations. If you want heavy reference-screenshot use, switch to Path A (free ChatGPT, no per-message image cost). For Path C, attach a reference to your FIRST build message only or rely on the vibe vocab fallback.

### 2. First prompt. Paste the assembled prompt from Prompt 17, click Build.

One message. The full assembled prompt that Claude synthesized in [Prompt 17 Bolt build prompt](/docs/prompts/bolt-build). Don't summarize, don't paraphrase, don't fill in placeholders by hand. Claude already did that.

The prompt opens with a "FIRST INSTRUCTION" block that tells Bolt to delete every file in the project except index.html before doing anything else. That handles the auto-scaffolded Vite tree.

Click **Build now** directly. Don't toggle Plan. Wait 60 to 120 seconds for the page to scaffold.

### 3. Review the scaffold AND the file sidebar

You'll get a full working page in 60 to 120 seconds. Don't prompt yet. Two things to check:

1. **The preview pane**. Does the page render? Does it look anything like the vibe?
2. **The file sidebar**. Does the project contain ONLY `index.html`? If you see `package.json`, `vite.config.js`, `main.js`, or any `src/` folder, the scaffold-strip didn't fully take.

If you see extra files, send one follow-up prompt: "Delete every file in the project except index.html. The project must contain exactly one file." Don't iterate on the page until the file tree is clean, otherwise every follow-up will keep re-syncing the Vite tree.

After the file tree is clean, read the page top to bottom. Click around. Decide what's actually wrong vs. what just needs a tweak.

### 4. Tweak via code edits, not prompts

For copy edits, hero image swaps, color tweaks, padding changes, individual section content: open `index.html`, edit the line, save. Zero tokens. Most refinement happens here.

For one-line code changes (rename a variable, change a className): same. Edit directly.

### 5. Re-prompt only for restructures

If you need a layout change that touches multiple sections, a feature you forgot to specify, or a bug you can't track down by editing: prompt Bolt. One change per prompt. Use the keep / change / add pattern from [Principle 6](/docs/vibecoding/principles).

If a single section is wrong (copy off, layout broken), almost always faster to edit it directly in `index.html` than re-prompt.

### 6. Publish

Bolt's Publish button is one click. Your URL ends in `.bolt.host` (or you can connect a custom domain on a paid plan). For free tier, the bolt.host subdomain is fine for the weekend launch.

Drop the URL in #launches before tonight's check-in.

## What good looks like

A 60-min build. One initial prompt that scaffolds the whole page in one go. 1 to 2 follow-up prompts max for restructures. The rest is direct code edits in `index.html`. Token budget under 100K of the 300K daily cap. Live URL in #launches by Friday night.

## What bad looks like

A 4-hour build. 30+ prompts. Every fix breaks two other things. Token budget gone before the page is even live. Toggling Plan mode on (it reads the auto-scaffolded Vite tree and burns 200K+ tokens before any code runs). Letting the Vite scaffold persist after the first build and re-ingesting it on every follow-up.

## When you hit the wall

You see "You've used all your tokens" mid-build. Bolt's free tier daily cap is 300K tokens, monthly is 1M. A Next.js scaffold burns 50K+ per prompt because Bolt re-reads the entire project tree on every message. A single-file HTML build keeps re-syncs cheap, so most founders don't hit the cap in a day. If you do, three options.

### Option 1. Wait for the daily reset (free, slow)

Bolt's daily cap resets on its calendar day (UTC-based). If you hit the wall at 3pm, you're back at 0 tokens around midnight UTC the same day, or 24 hours later depending on usage start. Loses momentum. Only viable if you have time to wait.

### Option 2. Migrate to Cursor (free, recommended)

Cursor is a code editor with built-in AI (Claude, GPT) and a free tier with no per-message token cap for typical landing-page work. Migration takes 30 minutes once you know the steps.

1. In Bolt, click your project name top-left, then Export, then Download. You get a zip of the project files.
2. Unzip the folder somewhere you can find. Open it in [Cursor](https://cursor.com) (free download, sign up free).
3. In Cursor's chat panel, toggle the **Agent** button on (most common newbie miss). Without Agent mode, Cursor won't edit files for you.
4. Ask the Agent: "install dependencies and run the dev server" (only needed if Bolt scaffolded a framework; for single-file HTML you can just open `index.html` in a browser).
5. Recreate any environment keys manually. Bolt does not export Supabase, Stripe, or other API secrets.
6. Continue iterating in Cursor's chat with the same one-change-per-prompt discipline.
7. Deploy: drag the folder onto [Netlify Drop](https://app.netlify.com/drop) for an instant free URL. Or push to GitHub and connect [Vercel](https://vercel.com) for a custom subdomain.

The hero you already built comes with you. No rebuild.

### Option 3. Pay for Bolt Pro (fast, costs money)

$20/month for 33x more tokens. One month covers a full sprint with room to iterate freely. Cancellable. Pick this if you want to keep Bolt's UX and don't mind the spend.
